### Doc 01 — Core Data Model

- **Producer identity.** [Necessary] A location could in principle hold more than one producer of the
  same kind (e.g. two manufactories on different methods). Producers are keyed by
  `(location, kind, method)`, treated as unique per location — one producer per kind+method.
  `placement` (Doc 02) creates a new producer only when no producer with that key exists yet. If a
  scenario ever needs two manufactories on the *same* method in one location, this will need
  revisiting.
- **`PrevSnapshot` scope.** [Necessary] The lag-rule snapshot's exact fields only become clear as Docs
  02–05 are written. Doc 01 ships `PrevSnapshot` with the fields already implied (`r_bar`, market
  `price`, per-record `f_N`) and each later doc extends `PrevSnapshot.take()` rather than redesigning
  the type. (The "annual wage bill" lag Doc 01 anticipated here turned out not to need a world-level
  snapshot at all — Doc 02 gives each `Producer` its own `last_wage_bill` field instead, since it's
  read and written by the same step.)
- **`sim/__main__.py`** [Necessary → S1-D05-T6 replaces the stub] is required by Doc 01's acceptance

### Doc 02 — Economy Engine

- **The consumption/hoard propensity split, resolved once.** [Necessary] "residual = income -
  consumption; saved = p*residual" reads as if the split is independent of the consumption function,
  but applying a propensity split twice (once implicitly in how much standing consumption happens,
  again in the hoard rule) either double-counts or drops value. `engine/consumption.py` resolves it
  in one pass: subsistence and comfort fill to their targets, then the leftover splits between
  standing spend and `saved` via the *same* propensity, and `saved` is handed to
  `engine/capital.py`'s `hoard_update` as an already-known number rather than recomputed from
  `income - consumption`.
- **`record.income` as a running, step-mutated flow.** [Necessary] Steps 1-3 add to it (wages,
  profit, rent — taxation once Doc 05 exists); step 5 replaces it with the saved residual; step 7
  consumes that and zeroes it. `record.last_gross_income` preserves the pre-consumption figure for
  mobility's income-per-head comparisons at step 8, since step 5 has already overwritten `income` by
  then.
- **Tier access by class.** [Necessary] Degrees-of-access, not a hard cutoff. Implemented as a hard
  cutoff only at the extremes: `SUBSISTENCE_ONLY_CLASSES` (hunters, herdsmen, serfs, retainers,
  servants, soldiers) never reach comfort/standing; every other class can reach all three tiers, with
  the tier logit's own price/weight terms naturally producing thin standing spend for the classes
  that should have only thin access, rather than a separate cap.
- **Comfort's target has no external anchor.** [Unneeded — literal `0.5` in step code violates
  convention; S1-D02-T10 moves it to `ConsumptionParams.comfort_target_multiplier`] Only subsistence
  has a clear basket-based target; comfort's target is `0.5 x the subsistence target`, a tuned
  placeholder.
- **No Luxuries reachable means a hard 0 weight, not vanity's floor.** [Necessary] `vanity()` never
  drops below `v_min` (it rises and saturates — it's not defined at 0 reachable luxuries in the same
  curve). But zero reachable Luxuries means *all* standing is Attendance, so `consume()` gates the
  Luxuries CES weight to exactly 0 when `last_supply[LUXURIES] == 0`, rather than feeding
  `vanity(0, ...) = v_min` into the CES share (which would give Luxuries a small but nonzero share
  even with nothing to buy).
- [Necessary for sweep 1; revisit in S2-D08-T2 if manufactories never light] **Producer input
  consumption (Materials into Wares, ore/coal into Arms, etc.) is pinned at a 1.0 multiplier**, not
  drawn down from `Market.inventory`. A true simultaneous input-output market clearing is out of
  scope for a first pass; Hunting, Herding, and Field (everything the opening bands can actually
  reach without a law being enacted) run the full formula, and Workshop/Manufactory/Mine/Port have
  the right *shape* with the input term fixed at 1.0 pending a later pass.
- **Herding's contribution to `r_bar`'s numerator is `ΔHerd`** [Necessary] (the herd's growth this
  year), not its split-rule profit share from selling Provisions/Materials — both income streams
  reach the owner, but herd increase specifically substitutes for the usual profit term when
  computing the average rate of profit.
- **Output composition ratios** [Necessary → S1-D08-T3 tuning] (`OUTPUT_MIX`, e.g. Hunting 0.8
  Provisions/0.2 Materials, Manufactory 0.6/0.2/0.2 Wares/Luxuries/Arms) are tuned placeholders —
  Doc 08's tuning pass should revisit these against actual play data.
- [Necessary] **`placement` places the whole freed-plus-reinvested pool into the single best-return
  producer each year**, rather than splitting continuously across every eligible producer in
  proportion to return. Stock still gravitates to the best return; it just moves in one lump per year
  instead of many small ones.
- **The band stage runs automatically, not through the action queue.** [Necessary; S2-D06 scripts
  call the same functions] Move/follow/settle read as sovereign choices in principle, but Doc 06's
  scripted AI doesn't exist yet in sweep 1 and a genuinely null sovereign would leave a band motionless
  forever — a band needs no government at all to function. `engine/band.py`'s `step_band` runs simple
  survival heuristics (move if depleted, follow herds, tame once contact crosses a threshold, settle
  when arable) automatically for any BAND-seat nation, in addition to exposing the mechanics as plain
  functions a real sovereign can call instead. Taming and settling also fire directly on their
  resource/contact gates rather than waiting for Doc 03's Interest/law machinery to self-enact "Tamed
  animal to the tamer" — these are the events that create property in the first place, before
  government exists to legislate about it. The corresponding law is marked pre-enacted so Doc 03
  doesn't try to fire it again.
- **Mobility's law-free scope.** [Necessary] `engine/mobility.py` implements the three
  wealth-threshold vertical promotions that need no law (herdsman -> herd-owner, craftsman ->
  capitalist, labourer -> craftsman) and the horizontal edges within each tier (same-location and
  cross-location, same nation). Vertical edges gated by a law (Commutation, Enclosure, a closing
  guild) are deliberately left to Doc 03, which applies them through the
  `EffectSpec("vertical_flow", ...)` tags already on those laws in `core/laws.py`, calling this
  module's `vertical_flow` directly. `edge_friction` always returns 0 in Doc 02 (no laws are enacted
  yet in its own scope); Doc 03 extends it once law state exists to read.
- **Retainer/servant dismissal flows to LABOURERS.** [Necessary] `engine/consumption.py`'s dismissal
  check (when a location's Attendance purchase falls through `dismissal_threshold`) routes the
  displaced headcount there directly, since dependents own no wealth to carry.
- **Tunable constants with no external name** [Necessary] (comfort's target multiplier, the vertical
  promotion wealth threshold, band contact/conversion rates, `BASE_RETURN_RANK` for placement, the
  internal goods-flow transport-cost floor) live in `Params` as new fields alongside the named ones,
  per the "no literal constants in step code" convention.

### Doc 03 — Politics and Unrest

- **`PROTECTION_OF_PROPERTY` is a handover, not a demand-table entry.** [Necessary] The named demand
  tables don't list it; it fires directly (`on_protection_of_property`), structurally parallel to
  `on_tamed_animal`, rather than cycling it through `politics/interests.py`'s `DEMANDS`.
- **Its firing condition is not the self-enactment bar verbatim.** [Necessary] The obvious choice —
  Landed authority vs. `theta' * (A_S + opposing authority)`, the same bar `self_enact` uses for
  cycled demands — is self-defeating by construction here: `on_tamed_animal` *initialises* `A_S` from
  a herd-owner's authority in the first place, so at the moment a nation becomes eligible for this
  check, `A_S` already starts at or above the very Landed authority the bar would need to beat, and
  `A_S` decays slower (5%/yr) than a shrinking population's authority, so the gap only widens —
  verified empirically against `scenarios/three_bands.yaml`, where no nation ever cleared that bar in
  300 years. `protection_of_property_condition` instead compares Landed's authority against a nominal
  weak-government baseline (`theta' * consensus_c0`, reusing the existing band-consensus constant as
  "what a minimal government commands") rather than against the nation's own (Landed-derived) `A_S`.
  With this gate, both `three_bands.yaml` nations that tame herds reach `seat == STATE` within a few
  years of taming — taming creates stakes worth defending, which is what motivates government, far
  better than the self-defeating alternative.
- **The State record's location.** [Necessary] There is no "capital" concept yet; `on_protection_
  of_property` places the State record at the nation's most populous location (a reasonable stand-in
  pending Doc 05/07, which may introduce a real capital idea).
- **`DEMANDS` omits demands with no `LawId`-level equivalent** [Necessary → S1-D04-T5 adds the charter
  demand once routes exist; S1-D05-T1/T2 add the Moneyed demands once finance exists]: "Poor Rate on
  others" (LANDED; the one `POOR_RATE` law in `LAW_TABLE` is opposed *by* Landed, not demanded by it —
  no way to express "funded by others" at this granularity), "tariffs on rival Wares" (INDUSTRIAL; no
  rival-specific law exists), "a charter on a closing route" (MERCHANT; route-specific, Doc 04),
  "service by land tax" and "no default" (MONEYED; finance mechanics, Doc 05). Mapping these to a
  nearby-but-wrong law would be worse than omitting them. `Repeal(LawId.GUILD_CHARTER)` is placed
  under INDUSTRIAL (the capitalists' side, who want manufactories unblocked) rather than under a
  craftsmen-vs-capitalists split `InterestId` can't represent (both are INDUSTRIAL).
- **Repeal has no separate formula.** [Necessary] `_repeal_bar` reuses `bar`'s formula with support
  and opposition swapped (repealing a law must overcome those who support it) — a natural symmetric
  reading, not stated explicitly elsewhere.
- **Enforcement's epsilon floor.** [Necessary] `enf_law = J*A_S/(A_S+opposition)` hits exactly 0
  whenever `A_S=0` and any interest opposes the law, contradicting the "never zero" rule for
  enforcement. `enforcement()` floors the result at a new `politics.enforcement_epsilon` (1e-3, tuned
  placeholder).
- **`self_enact` fires at most one law per Interest per year.** [Necessary] Nothing says whether an
  Interest can clear its whole demand table in a single year; capping it at one avoids a single year
  dumping an Interest's entire agenda into law and keeps `A_S`/authority interactions (each
  self-enactment changes the state other demands are evaluated against) meaningful year to year.
- [Necessary] **`dependents_r` is apportioned by Attendance spend share.** RETAINERS/SERVANTS are one
  record per location bought by several buyer classes at once; a buyer's own dependents are estimated
  as `dependent_record.size * (buyer's Attendance spend / total Attendance spend by that dependent
  class's buyers)` — the only information the model keeps linking a dependent headcount back to a
  particular buyer.
- [Necessary] **`nation.events_this_year` is a ledger query, not a stored list on `Nation`.** The
  ledger is already the single append-only event store; `politics.state.events_this_year(nation_id,
  world)` filters `world.ledger.events_in_year(world.year)` by nation rather than duplicating that
  state.
- **`on_tamed_animal`'s handover is called from `engine/band.py`'s `step_band`** [Necessary] (Doc 02's
  file), not from anywhere in `politics/`. `band.py` fires taming directly on its resource/contact
  gate rather than through `self_enact` (Doc 02's own documented simplification), so nothing in the
  legislative pipeline ever observes that enactment; Doc 03 adds one call
  (`politics.state.on_tamed_animal`) right after `tame_herd` succeeds, the smallest possible touch to
  a module Doc 03 doesn't own. `on_tamed_animal` itself computes the herd-owner's authority fresh (via
  `authority.record_authority`) rather than trusting `record.authority`, since the record can be
  created this same year, before step 12a has run on it.
- [Necessary] **`walk_away_multiplier` and `vertical_flow` law effects are applied continuously (every
  year the law is enacted), not once at enactment.** Both depend on the law's current `enforcement`,
  which drifts year to year; a one-shot application at enactment time would freeze them at that year's
  enforcement. `_apply_continuous_law_effects` runs after each year's fresh enforcement computation,
  inside `step_legislation`. For `vertical_flow`, a `forced=True` edge (Enclosure) converts at a share
  equal to enforcement itself (fast); an unforced edge (Commutation) converts at the law-free
  promotion rate (`mobility.rate_v_base`) scaled by enforcement (a trickle) — there is no separate
  rate for law-gated vs. law-free edges, so the law-free rate is reused as the "gradual" case.
- **`SERFDOM`'s `walk_away_multiplier` effect.** [Necessary] The nominal rule ("0 x
  enforcement(Serfdom)") is degenerate as a formula (0 times anything is 0, so full or zero
  enforcement give the same walk-away). Read instead as "0 under full enforcement, the class's free
  baseline (1.0) under none": `walk_away = base + (1-base) * (1-enforcement)` with `base=0.0` from
  `LAW_TABLE`'s `EffectSpec`.
- **`engine/mobility.py`'s `edge_friction` extension is approximate.** [Necessary → S1-D04-T4 supplies
  the real cross-border friction] Doc 02 left this function (same-location `(from_cls, to_cls)`
  friction) as an explicit extension point for Doc 03, but neither of `LAW_TABLE`'s two
  `friction`-tagged laws actually names a same-location class pair: Settlement Law's tag is
  `free_labour_cross_location` (a *cross-location* edge) and Apprenticeship's is `producer` (hiring
  friction, not a mobility edge at all). `edge_friction` approximates both as same-location damping —
  Settlement Law on the free-labour tier (LABOURERS/SOLDIERS), Apprenticeship on any edge touching
  CRAFTSMEN — using the `x` magnitude already declared on each law's `EffectSpec` in `LAW_TABLE`
  rather than a new literal. This is a best-effort reading, not a precise implementation of either
  tag; a true cross-location/producer-hiring friction mechanic is left for whichever doc builds those
  edges' real consumers.
- **`state_authority_update` omits the `-spent` term from its yearly recurrence.** [Necessary]
  Spending on enactment/repeal/veto/Focus-upkeep is deducted immediately at the point of expenditure
  (so `actions.validate` can gate a sovereign from overspending within a year against the same
  running `A_S` balance); re-subtracting a `spent` figure in the yearly recurrence would double-count
  it.
- [Unneeded → S1-D04-T2 corrects it to read the active doctrine] **`R_private` (lords' armed
  retainers) reads whether `FEUDAL_HOST` has ever been lit**, not whether it's the *active* doctrine —
  doctrine-switching tracking is Doc 04's (`0` until Docs 04/06 wire it, the same "0 until then"
  pattern used elsewhere for `M_state/M`).
- **New `Params` fields with no external symbol** [Necessary] (`radicalism_decay`, `veto_premium`,
  `enforcement_epsilon`, `focus_upkeep`, `justice_need_per_head`, `focus_gate_rate`,
  `focus_gate_rate_education`): tuned placeholders, following Doc 02's precedent.
- **`focus.advance_focus`'s gate-reduction magnitude** [Necessary → S1-D05-T3 consumes it] is a
  placeholder linear function of accumulated progress; what each Focus kind *does* (carriage factor /
  patent exclusivity / skill-penalty reduction) is named, but the actual gate-lowering mechanic is
  explicitly Doc 05's (`evaluate_gates` doesn't exist yet), so this only produces a number for Doc 05
  to consume, not a wired effect.
